# 主实验与商用补充方案

## 推荐投稿方案

### 1. 主实验

- 主模型：`Qwen2.5-7B-Instruct`
- 运行方式：本地 `transformers`
- 作用：作为论文主结果来源

理由：

- 可复现
- 可本地固定版本
- 比 `1.5B` 更适合作为正式论文主模型
- 比纯商用 API 更容易回应审稿人的复现性质疑

### 2. 商用补充实验

- 推荐模型：`gpt-5.4-mini`
- 运行方式：OpenAI API
- 作用：做子集泛化验证，不承担全文主结果

理由：

- 输出稳定
- 成本相对低
- 比免费或预览型商用模型更适合作为正式论文补充证据

## 不推荐作为唯一商用主模型的方案

### 免费或预览方案

如果目标是最低成本，Google 的低价或免费层模型可能更便宜，但不适合作为唯一正式主结果，原因包括：

- 免费额度和预览状态容易变化
- 模型版本可能调整
- 复现性和稳定性不如固定开源主模型

因此，免费或预览商用模型更适合：

- 预实验
- prompt 调试
- 附录补充

不适合：

- 作为整篇 SCI 论文唯一核心实验模型

## 建议的论文口径

推荐写法：

1. 本文主要在本地可复现的 `Qwen2.5-7B-Instruct` 上进行完整实验。
2. 为验证方法对更强商用模型的迁移性，在 `gpt-5.4-mini` 上进行分层抽样子集实验。
3. `Qwen2.5-1.5B-Instruct` 只作为轻量效率设置，用于补充成本与资源约束分析。

## 商用补充实验费用估算

当前补充实验配置默认是：

- `5` 个产品
- `4` 类受众
- 共 `20` 个任务
- 只跑 `5` 个主方法
- `Ours` 使用 `2 rounds x 2 candidates`

在这个设置下，总文本调用数约为：

- 每任务 `7` 次模型调用
- 全部约 `140` 次调用

费用估算脚本：

- `scripts/estimate_openai_cost.py`

运行方式：

```powershell
python scripts/estimate_openai_cost.py --config configs/real_experiment_config_openai_mini_subset.json
```

默认估算基于：

- 基准假设：每次调用输入 `420` tokens，输出 `120` tokens
- 高位假设：每次调用输入 `650` tokens，输出 `180` tokens

这适合在论文中写成 “estimated API cost under practical prompt-length assumptions”，而不是假装是精确账单值。

## 推荐执行顺序

1. 先下载并跑通 `Qwen2.5-7B-Instruct`
2. 跑完整主实验
3. 用 `gpt-5.4-mini` 跑 `5` 到 `10` 产品的子集补充实验
4. 在论文中将商用结果写成 cross-model validation，而不是主结果
